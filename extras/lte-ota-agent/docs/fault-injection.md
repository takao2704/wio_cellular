# 実機障害注入試験

保守担当者が、不完全・破損したイメージを適用しないことと、中断後の動作を確認する手順です。
[過去の実測記録](https://github.com/takao2704/wio_cellular/blob/873ded2438b8083a7f001cde241c6e2962187a54/extras/lte-ota-agent/docs/validation/README.md)はforkの固定コミットから参照できます。
PC上の検証は[回帰テスト](../tests/README.md)で実行します。

## 準備

- 対象端末、現在のアプリ識別値、正常起動を確認する
- 手動USB DFUと正常アプリの書戻し手段を確保する
- Metadataユーザーデータと配信バイナリの変更前の内容を保存する
- 更新し続けることのない試験用SIMグループへ限定する
- 電源・通信の切断タイミングを実施者と確認し、1ケースずつ行う

通信断と装置全体の電源断は別に扱います。Wio本体のRESETではセルラーモジュールはリセットされません。
ダウンロード中断試験には`kDownloadAndVerify`を返すアプリ、
または意図的にCRCを不一致にした未署名の試験manifestを使い、
切断が遅れて受信が完了しても適用されないようにします。
未署名の試験設定は本番運用へ使わないでください。

## manifest・HTTP応答・イメージ

| 注入内容 | 期待結果 |
|---|---|
| 対象HW不一致、サイズ不正、許可外host | manifestを拒否し、イメージを取得しない |
| 存在しないURL、Content-Length不一致 | 応答を拒否し、適用しない |
| CRC16・SHA-256不一致 | 全量取得しても検証失敗として適用しない |
| 署名後のmanifest改変 | 署名検証で拒否し、イメージを取得しない |
| 正しく署名された旧版 | アンチロールバック有効時に拒否する |

署名済みmanifestのサイズやCRCを編集すると、イメージ検証より先に署名で拒否されます。
試験対象の層に合わせて再署名するか、隔離した試験端末でのみ署名なし設定を使います。

## 取得中の中断

| 注入内容 | 確認すること |
|---|---|
| HTTP取得・UFS保存中にLTE通信を失わせる | 取得が失敗し、適用登録しない |
| UFSからBank 1への書込み中にWioをRESET | 不完全なBank 1を適用せず、現在アプリが起動する |
| 同じ処理中に装置全体の電源を切断 | 再投入後に現在アプリが起動する |

BG770Aは本文全体をUFSへ保存してからMCUへ渡します。
進捗ログが出た後のLTE切断では、UFSからの読出しは中断しません。
通信断は`GET firmware image`から`UFS response stored`までの間に行います。
次の試行は先頭から取得します。途中再開はありません。

## 適用登録の前後で停止する試験

専用環境は`tests/hardware/platformio.ini`にあります。
通常のexampleには停止用環境や停止ログを含めていません。
コマンドはOTAプロジェクトのルートで実行します。

```bash
pio run -d tests/hardware -e before_activation
pio run -d tests/hardware -e after_activation
```

どちらも同じ利用例をアプリ識別値2でビルドします。
運用済み端末を試験する場合は、現在の識別値と配信manifestに合わせて設定してください。
この設定は署名なしの隔離試験用です。自動アップロードや自動電源断は行いません。

| 環境 | 停止地点 | RESET後の期待結果 |
|---|---|---|
| `before_activation` | イメージ検証後、bootloaderへの登録前 | 更新を適用せず、現在アプリが起動 |
| `after_activation` | 登録成功後、ソフトウェアリセット前 | bootloaderが登録済みイメージを適用 |

1. 正常アプリのUSB復旧を確認したうえで、選んだ試験用アプリを手動で書き込む。
2. 検証が成功する更新イメージとmanifestを試験グループに配置する。
3. `[OTA TEST]`の停止ログを確認する。
4. 再起動後に再び更新を始めないよう、Metadataを「更新なし」となる正常値へ戻す。
5. 通常RESETを押し、起動したアプリと適用結果を記録する。

試験中だけライブラリへ`WIO_OTA_TEST_HALT_BEFORE_ACTIVATE`または
`WIO_OTA_TEST_HALT_AFTER_ACTIVATE`を渡します。
このフラグを指定すると処理は意図的に停止します。本番ビルドへ指定しないでください。
フラグを指定しない通常ビルドには停止処理は入りません。

bootloaderコピー中やsettings書込み中の電源断は、この停止試験では検証できません。
別途承認し、SWD等で全領域を復旧できる状態で行う試験です。
