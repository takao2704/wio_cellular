- Board: Seeed Wio BG770A HW v1.0

## 試験中に修正した不具合

USB転送プロトコルのヘッダーはSHA-256を含めて82文字だが、bootstrapのコマンドバッファが64文字だったため途中で切れていた。バッファを96文字へ拡張した。また、検証のみの転送後にwriterをidleへ戻す`discard()`と、host側から明示的に`ABORT`する処理を追加した。

## M3: LTE経由の取得とBank 1検証

配信元は次のSORACOMサービスを使用した。

- manifest: Metadata Serviceのユーザーデータ
- firmware: Harvest Filesのバージョン別パス

対象SIMのグループでMetadata（read-only）とHarvest Filesを有効化し、Globalカバレッジ側へM2と同じ46,876-byteのraw firmwareを配置した。アップロード後に再取得してSHA-256が一致することを確認した。

実機ではLTE attach、PDP activation、SORACOM閉域pingに成功し、次のHTTP応答を得た。

```text
[HTTP] manifest status=200 length=244
[OTA] downloading version=2 size=46876
[HTTP] firmware status=200 length=46876
```

最初に試した`QHTTPREAD`によるUARTへの本文一括出力では、32 KiB通過後に本文タイムアウトとなった。WioCellularが使用するUART受信リングは64 bytesであり、受信とnRF52840内蔵Flash書込みを同時に行う構成では余裕がないため、HTTP応答をBG770A内UFSへ保存してから読み出す方式へ変更した。

採用したフロー:

```text
QHTTPGET
  -> QHTTPREADFILE (UFSへ保存)
  -> QFOPEN
  -> QFREAD (512 bytesずつ)
  -> Bank 1へ書込み・read-back比較
  -> QFCLOSE / QFDEL
  -> CRC16 / SHA-256 / vector table検証
```

実機結果:

```text
[HTTP] UFS response stored
[HTTP] UFS file opened handle=0
[HTTP] UFS first read payload=512
[OTA] progress 16384/46876
[OTA] progress 32768/46876
[OTA] progress 46876/46876
[OTA] image verified
[OTA] verified only; WIO_OTA_AUTO_APPLY is disabled
[STATUS] phase=ota-check-complete sim=...<LAST4>
```

これにより、SORACOM Metadataで更新情報を取得し、Harvest FilesからLTE経由でraw firmwareを取得してBank 1へ保存し、M2と同じCRC16 `0x0843`およびSHA-256を検証するM3の完了条件を満たした。自動適用は無効のため、この試験ではBank 0とbootloader settingsを変更していない。

## M5: manifest対象不一致

`cellular-status-ota` version 2を動作させたまま、Metadataのmanifestで
`hardware`だけを`wio-bg770a-v1.0-m5-mismatch`へ一時変更した。Metadataは
enabledかつread-only、version、size、CRC16、SHA-256、firmware URLは正常値を
維持した。

実機をresetして次のログを確認した。

```text
[LTE] network ready
[HTTP] modem HTTP client configured
[HTTP] GET metadata manifest
[HTTP] manifest status=200 length=249
[OTA] failed: manifest fields invalid
[OTA] result=failed
[APP] version=2 uptime=17
```

`GET firmware image`は出力されず、Bank 1への書込みや適用も開始されなかった。
その後もversion 2は5秒間隔で稼働ログを出力した。試験直後にmanifestの
`hardware`を`wio-bg770a-v1.0`へ戻し、Metadataがread-onlyのまま正常値へ
復元されたことをAPIで読み戻した。再度resetし、復元後の実機でも次を確認した。

```text
[HTTP] manifest status=200 length=237
[OTA] application reports no update
[OTA] result=no update
[APP] version=2 uptime=15
```

失敗後の次回確認が正常に実行され、version 2の継続動作を確認できたため、M5 A1を
PASSとする。

## M5: firmwareのCRC16不一致

manifestのversionを3にして更新判定を通過させ、正常なfirmwareに対してCRC16だけを

M5 A6をPASSとする。

## M5: download中のWio本体reset

B2では、version 3かつCRC16不一致のmanifestを安全ガードとして使用した。Wio本体を
resetしてdownloadを開始し、次の進捗を確認してから再度resetした。

```text
[OTA] downloading version=3 size=129084
[HTTP] firmware status=200 length=129084
[OTA] progress 16384/129084
[OTA] progress 32768/129084
Disconnected (read failed: Device not configured)
Reconnecting to /dev/cu.usbmodem101 ... Connected!
```

reset直後に正常なversion 2のmanifestへ戻したが、端末はMetadataの旧値を一度取得し、
version 3を先頭から再downloadした。この再downloadも80KB台でresetした。Metadataの
正常値が反映された次の起動では、次を確認した。

```text
[HTTP] manifest status=200 length=237
[OTA] application reports no update
[OTA] result=no update
[APP] version=2 uptime=15
```

いずれのresetでもbootloaderは未完成のBank 1を適用せず、現在のversion 2を起動した。
また、現実装は途中位置から再開せず先頭から再取得することを確認した。Metadata更新は
端末から見える値へ即時反映されない場合があるため、中断試験後の復旧ではAPI readback
だけでなく、端末の`no update`ログまで確認する。M5 B2をPASSとする。

## M5: UFSからBank 1への書込み中にLTE sessionを削除

B1の通信断を狙い、CRC16不一致の安全manifestでdownloadを開始した。Bank 1の進捗が
32,768 / 129,084 bytesに達した時点で、対象SIMのstatusを変えずにSORACOM APIから
現在sessionを削除した。

```text
[OTA] progress 32768/129084
[OTA] progress 49152/129084
[OTA] progress 65536/129084
URC> +CEREG: 0
URC> +CEREG: 2
URC> +CEREG: 5
[OTA] progress 81920/129084
...
[OTA] progress 129084/129084
[OTA] writer failed: CRC16 mismatch
[OTA] result=failed
[APP] version=2 uptime=85
```

LTE sessionの切断と再接続は確認できたが、Bank 1書込みは中断しなかった。BG770Aの
HTTP responseはこの時点ですでにUFSへ保存済みであり、MCUはネットワークではなく
UFSを読み出していたためである。CRC16不一致により有効化は行われず、version 2が
継続した。正常manifestへの復元もAPIで確認した。

この結果は障害時の挙動として有効だが、B1のネットワークread失敗条件は満たさない。
B1は`GET firmware image`から`UFS response stored`までのHTTP取得中にsessionを削除する
方法へ修正して再試験する。

## M5: HTTP取得・UFS保存中のLTE session断

B1の再試験では、通信断をHTTP取得パイプラインへ確実に重ねるため、通常の129,084
bytesではなく、最大アプリサイズと同じ397,312 bytesの一時ファイルをHarvest Filesへ
配置した。manifestはversion 3とし、CRC16だけを実値から1 bit反転して安全ガードにした。

実機をresetし、manifest取得完了後から対象SIMのsession削除を6回行った。SIMのstatusは
activeのまま変更していない。

```text
[HTTP] manifest status=200 length=246
[OTA] downloading version=3 size=397312
[HTTP] GET firmware image
[HTTP] firmware status=200 length=397312
[HTTP] failed: firmware read failed (file store failed)
[OTA] result=failed
[APP] version=2 uptime=35
URC> +CEREG: 5
URC> +CEREG: 0
URC> +CEREG: 2
URC> +CEREG: 5
```

HTTP GETはstatus 200まで完了したが、BG770A内でresponseをUFSへ保存する処理が通信断中に
失敗した。Bank 1のpayload書込み進捗は出ず、writerは破棄され、bootloader settingsの
有効化も行われなかった。version 2は再起動せず継続動作し、LTE sessionも再接続した。

試験直後にversion 2の正常manifestへ復元し、一時Harvest Filesを削除した。APIで
Metadataがenabledかつread-only、対象SIMがactiveかつonlineであることを確認した。
M5 B1をPASSとする。

[HTTP] GET metadata manifest

[OTA] result=no update

## M5: verify完了後、activate前のreset

C1専用の`ota_v2_m5_c1`をUSB DFUで書き込んだ。この環境では正常な受信・検証後、
`writer.activate()`を呼ぶ直前で停止する。通常ビルドには停止処理を含めない。

version 3のmanifestから通常v2の129,084-byteイメージを取得し、次を確認した。

```text
[OTA] progress 129084/129084
[OTA] image verified
[M5] verified; halted before activate; press RESET
```

停止中にversion 2の正常manifestへ復元してからWio本体をresetした。再起動後は次を
確認した。

```text
[HTTP] manifest status=200 length=237
[OTA] application reports no update
[OTA] result=no update
[APP] version=2 uptime=16
```

検証済みイメージがBank 1に存在していても、bootloader settingsへ登録される前のreset
では適用されず、現在のversion 2が起動した。M5 C1をPASSとする。

## M5: activate完了後、software reset前のreset

C2専用の`ota_v2_m5_c2`をUSB DFUで書き込んだ。この環境では正常な受信・検証後に
`writer.activate()`でbootloader settingsを登録し、software resetの直前で停止する。

version 3のmanifestから通常v2イメージを取得し、次を確認した。

```text
[OTA] progress 129084/129084
[OTA] image verified
[M5] settings committed; halted before software reset; press RESET
```

停止中にversion 2の正常manifestへ復元し、Wio本体を物理resetした。USBは再列挙され、
通常v2アプリがLTEへ接続して次を出力した。

```text
[LTE] network ready
[HTTP] manifest status=200 length=237
[OTA] application reports no update
[OTA] result=no update
[APP] version=2 uptime=18
```

settings登録後にsoftware resetへ進む前で停止しても、次の物理resetで登録済みBank 1を
bootloaderが処理し、通常アプリを起動できた。M5 C2をPASSとする。

M5 A1〜C2は完了した。Bank 1からBank 0へのcopy中に電源を切るC3は、SWD復旧手段を
